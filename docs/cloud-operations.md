# Cloud operating and recovery runbook

Operate from an approved release manifest and a protected, short-lived identity. The tools accept real Terraform outputs; they do not invent resource names or records. Admission, executor and database-owner credentials remain separate. Serialize releases and recovery; the protected workflow uses one environment concurrency group with cancellation disabled.

## Observe and triage

CloudWatch EMF emits only environment/service dimensions. Customer identifiers, contact data, exception strings and tokens never become metric labels. Business correlation lives in the durable proposal ID, audit subject, lease token and remote receipt. Logs carry bounded operational signals; use the authenticated audit API or read-only SQL to investigate a specific intent.

| Signal | Default alarm / interpretation | Response |
|---|---|---|
| EligibleAgeSeconds | Maximum >120 seconds for three minutes | Check dependency failures, worker health, lease recovery and connection pressure before adding workers. |
| Uncertain | >20 unresolved jobs for three minutes | Treat as unknown business outcomes; look up original keys. Do not bulk reset IDs. |
| Dead | >0 for three minutes | Classify permanent rejection vs exhausted retry budget; requeue only after authorization and outcome review. |
| WorkerPoll | No heartbeat for three minutes | Check task exit, DB permissions, connectivity and missing secrets. Missing heartbeat breaches rather than silently appearing healthy. |
| DependencyFailure / ApiError | >5 per minute across three periods | Inspect authority, 429/5xx and connectivity. Confirm whether the fault happened before or after dispatch. |
| UnHealthyHostCount | >0 for two minutes | Check ALB health and `/health` DB access; ECS circuit breaker can roll back a failed revision. |
| FreeStorageSpace | <5 GiB for three minutes | Investigate retention, WAL and storage growth; preserve immutable evidence. |

`Retry`, `Reconciled` and `Backlog` support diagnosis. The observer emits queue values every 30 seconds; the worker heartbeat is per process. Thresholds are initial operating settings, not measured SLO commitments. Expected maintenance drains should suppress the associated paging action through the organization's incident process, then restore it. CloudWatch log retention is 90 days. RDS logging suppresses SQL error statements to avoid copying rejected customer payloads into operational logs.

## Release and immutable rollback

The release manifest binds image digest, source commit and named task revisions. The release role cannot register a new task definition. Infrastructure administration registers reviewed definitions; the release tool rejects any image or entrypoint that does not match its approved manifest.

```bash
python -m controlplane.release deploy --manifest release.json --record work/release-record.json
```

This is an explicit maintenance release: drain → migrate → verify → downstream → API → workers → observer. It favors clear migration/recovery boundaries over an unproven zero-downtime claim. A failed utility leaves service counts at zero. A service-start failure triggers another drain. ECS stability is checked against the exact requested task revision because a circuit breaker can become stable by rolling back.

Retain at least the previous tested image and manifest. ECR tags are immutable; no age-based image deletion rule is configured. To roll application code back:

```bash
python -m controlplane.release rollback --manifest previous-release.json --record work/rollback-record.json
```

Rollback does not downgrade the database or delete newer audit events. The current schema is migration version 1 with a checksum guard. Future migrations must use expand/contract compatibility across the rollback window; an incompatible schema needs forward repair or the restore procedure, not an automatic image rollback. A changed policy hash can block pending proposals instead of silently applying different rules. Record and review those exceptions.

## Credential failure and rotation

Missing, denied or malformed startup secrets terminate the task before it begins work. A rejected downstream credential produces a durable rejection; a failure while reconciling an unknown effect retains uncertainty and uses the retry budget. Do not treat a 401 on receipt lookup as evidence that no effect happened.

Secrets Manager values are loaded at task start. RDS owner credentials are managed by RDS; application credentials are generated by bootstrap and retained on restart. For application/token rotation: quiesce; update the affected version through the security administrator; update both worker and downstream executor tokens together; run the migration task to apply the corresponding database login password; run fresh verification and resume tasks. No secret value belongs in command history, Terraform variables, CI output or a GitHub environment variable. Use a protected SDK session reading values from the organization's secret-handling interface. Automatic runtime-token rotation is not configured; the coordinated sequence prevents mismatched credentials and hot-cache ambiguity.

## Point-in-time recovery

![Restore gate](diagrams/06-database-restore.svg)

1. **Declare the boundary.** Stop upstream admissions and other writers. Run `quiesce`; the tool closes all four services, waits for zero desired/running/pending counts, and refuses to continue if any one-off task is still running. Restrict release access to the incident owner for the recovery window. There is no autoscaler that can reopen services.

   ```bash
   python -m controlplane.release quiesce --manifest release.json --record work/quiesce.json
   ```

2. **Select the recovery point.** Preserve the original database and deployment manifest. Confirm RDS's reported earliest/latest restorable time and the incident timestamp. The helper checks that the selected timezone-aware timestamp lies within that window. It copies private subnet, SG, parameter group, Multi-AZ and managed-owner-secret settings to a new instance. It never restores the independent downstream store.

   ```bash
   python -m controlplane.restore --manifest release.json --target control-stage-restore-incident \
     --at '<reviewed-UTC-timestamp>'
   # After reviewing the request, the separately authorized recovery operator adds --execute.
   ```

   The helper checks real service/database state even in review mode. `--execute` submits the restore request; it does not claim completion. Wait for RDS `available` and confirm encryption, TLS parameters, subnet/SG attachments and the managed owner secret. Verify backups and alarms on the restored instance; restored-resource lifecycle is incident-owned until imported into the long-term state. RDS permissions belong to the recovery operator, not the GitHub release role.

3. **Bind while closed.** Set `restored_control_identifier` in the private environment configuration. Review/apply Terraform so the migration task can read the new owner secret and endpoint; export the new manifest. Services remain at zero. The bootstrap task rebinds application/verifier DSNs, keeps effect identities and application passwords stable, and reapplies the current role grants. It uses the existing version-1 checksum guard. Do not edit stored intents or their mutation hashes.

4. **Compare independent facts.** Run `deploy` with the new manifest while incident ownership excludes concurrent writers. It runs migration and a fresh read-only verifier before opening services. Alternatively run the migration one-shot from the manifest using the operator's ECS console, then `verify` for an inspection-only pass. The verifier compares **all** local intents and independent receipts, including remote IDs absent from local state; checking only uncertain jobs would miss the most serious restore gap.

   ```bash
   python -m controlplane.release verify --manifest release.json --record work/recovery-check.json
   ```

   | Finding | Required disposition |
   |---|---|
   | Remote receipt with no restored intent | Keep closed. Recover the missing immutable ledger from the original/WAL/audit evidence or select a later recovery point. Do not synthesize an intent or rekey the business action. |
   | Same key, different mutation hash or receipt | Identity conflict; preserve both records and investigate. Never overwrite the remote fact. |
   | Locally acknowledged success with no remote receipt | Downstream loss or inconsistent restore boundary; keep closed and reconcile independently. |
   | Matching receipt and uncertain nonterminal intent | Existing worker reconciliation can acknowledge the historical effect without sending another. |
   | Terminal or non-uncertain intent with an unexplained remote effect | Manual review; the automatic gate cannot authorize repair. |

5. **Resume only from a fresh pass.** `resume` reruns the verifier after checking quiescence, then starts exact approved revisions. It does not accept an old JSON pass as authorization. The verifier identity can read both ledgers but cannot dispatch, requeue or delete anything. During resume, workers reconcile existing keys and revalidate current permission before new dispatch.

   ```bash
   python -m controlplane.release resume --manifest release.json --record work/resume.json
   ```

6. **Close the incident.** Review unresolved intents, exceptions, policy revisions and downstream totals. Measure actual RPO as restored state versus incident time and unresolved business facts; measure RTO through verified resumption, not merely `DBInstanceStatus=available`. Record recovery timestamps and AWS task IDs only from the executed environment. Retain the original database until the data owner accepts the reconciliation.

The executable local test removes a committed intent from the control ledger while retaining its downstream receipt, then proves the gate refuses resume. SDK-stubbed tests cover credentials, immutable task bindings and failure-before-open. These establish recovery logic; an authorized environment must separately exercise managed RDS failover/PITR, regional dependencies, PKI, routing and paging delivery.
